## 项目简介

**GameControllerFramework** 是为游戏开发者和终端设备厂商提供的一套完整的游戏外设接入解决方案。该框架实现了游戏外设的监听、识别、输入转触控等核心能力。

### 核心价值

- **对游戏开发者**：提供稳定的CAPI接口，实现对游戏外设的上下线监听及输入事件监听
- **对终端厂商**：提供InnerAPI接口，实现对外设设备的识别信息管理以及输入转触控的配置管理
- **对游戏玩家**：通过输入转触控功能，在不需要游戏厂商适配的情况下，使用键盘、鼠标等外设玩游戏

## 核心特性

### 1. 设备监听能力

- ✅ 监听游戏外设上下线事件
- ✅ 获取在线设备信息（设备ID、名称、类型等）
- ✅ 自动识别设备类型（键盘、手柄、鼠标等）

### 2. 输入事件监听

- ✅ 监听手柄按键事件（32种按钮类型）
- ✅ 监听手柄轴事件（摇杆、扳机等）
- ✅ 支持多设备同时监听

### 3. 输入转触控（核心特性）

支持17种映射类型，将游戏外设输入转为触摸屏事件：

| 映射类型 | 说明 |
|---------|------|
| 单键转触控 | 按键映射为点击事件 |
| 组合键转触控 | 多键组合映射 |
| 方向键转触控 | 8方向移动支持 |
| 鼠标右键行走 | 鼠标控制角色移动 |
| 技能键 | 支持鼠标方向控制技能 |
| 观察视角键 | 第一人称视角控制 |
| 鼠标观察 | 鼠标控制视角 |
| 键盘观察 | 键盘控制视角 |
| 准心键 | FPS游戏准心控制 |
| 鼠标左键射击 | 鼠标左键开火 |
| 摇杆行走 | 手柄摇杆控制移动 |
| 摇杆观察 | 手柄摇杆控制视角 |
| 手柄技能 | 手柄技能释放 |
| FPS摇杆观察 | FPS游戏专用摇杆控制 |
| ... | 更多类型 |

### 4. 设备类型识别

- ✅ 自动识别键盘、手柄、鼠标等设备类型
- ✅ 支持精确匹配（产品ID + 厂商ID）
- ✅ 支持模糊匹配（设备名前缀）
- ✅ 支持折叠屏虚拟键盘识别

### 5. 配置管理

- ✅ JSON配置文件驱动
- ✅ 默认配置 + 自定义配置
- ✅ 支持多游戏、多设备配置
- ✅ 配置热更新

## 架构设计

### 分层架构

```
┌──────────────┐
│   应用层     │  游戏应用 / 终端厂商服务
├──────────────┤
│   接口层     │  CAPI / InnerAPI
├──────────────┤
│   框架层     │  业务逻辑实现
├──────────────┤
│   服务层     │  系统服务 (SA)
├──────────────┤
│  外部系统    │  窗口 / 多模输入 / samgr
└──────────────┘
```

### 核心模块

| 模块 | 功能 |
|------|------|
| **GameDevice** | 设备查询和监听API |
| **GamePad** | 手柄输入监听API |
| **KeyMapping** | 输入转触控核心逻辑（17种Handler） |
| **DeviceManager** | 设备类型识别和管理 |
| **KeyMappingManager** | 按键映射配置管理 |

## 技术栈

### 编程语言
- **C++11+** - 核心实现语言
- **C** - 公共API接口

### 框架和库
- **OpenHarmony System Ability (SA)** - 系统服务框架
- **IPC (Inter-Process Communication)** - 跨进程通信
- **ffrt (Function Flow Runtime)** - 异步任务调度
- **MMI (Multi-Modal Input)** - 多模输入系统
- **WindowManager** - 窗口管理

### 设计模式
- **单例模式** - 管理器类设计
- **策略模式** - 17种Handler实现
- **观察者模式** - 事件监听机制
- **代理模式** - IPC通信实现

## 应用场景

### 场景一：游戏开发者的使用

```c
// 1. 注册设备监听
OH_GameDevice_RegisterDeviceMonitor(DeviceEventCallback);

// 2. 注册手柄按键监听
OH_GamePad_ButtonA_RegisterButtonInputMonitor(ButtonCallback);

// 3. 在回调中处理事件
void ButtonCallback(GamePad_ButtonEvent* event) {
    int32_t deviceId = OH_GamePad_ButtonEvent_GetDeviceId(event);
    GamePad_Button_ActionType action = OH_GamePad_ButtonEvent_GetButtonAction(event);
    // 处理游戏逻辑...
}
```

### 场景二：终端厂商的配置管理

```cpp
// 1. 同步设备识别信息
GameControllerServerClient::GetInstance()->SyncIdentifiedDeviceInfos(deviceInfos);

// 2. 同步支持输入转触控的游戏列表
GameControllerServerClient::GetInstance()->SyncSupportKeyMappingGames(true, gameInfos);

// 3. 设置游戏的按键映射配置
GameControllerServerClient::GetInstance()->SetCustomGameKeyMappingConfig(config);
```

### 场景三：输入转触控特性

当游戏支持输入转触控时，框架会：
1. 自动拦截键盘/鼠标输入
2. 根据配置文件转换为触摸屏事件
3. 注入到游戏中，实现触屏操作效果
