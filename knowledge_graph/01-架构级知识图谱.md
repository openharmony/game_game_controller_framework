## 2. 主要组件及职责

| 组件名称 | 所在层 | 职责描述 | 关键文件路径 |
|---------|-------|---------|-------------|
| **GameDevice** | 接口层 | 提供游戏设备查询和监听API，获取所有在线设备信息，监听设备上下线事件 | `interfaces/kits/c/game_device.h` |
| **GamePad** | 接口层 | 提供游戏手柄输入监听API，监听手柄按键、摇杆、扳机等输入事件 | `interfaces/kits/c/game_pad.h` |
| **WindowInputIntercept** | 框架层 | 对接窗口系统，注册输入事件拦截，消费Key/Pointer事件 | `frameworks/native/window/src/window_input_intercept.cpp` |
| **MultiModalInputMonitor** | 框架层 | 监听多模输入SA的设备上下线事件 | `frameworks/native/multi_modal_input/src/multi_modal_input_monitor.cpp` |
| **KeyToTouchManager** | 框架层 | 输入转触控核心管理器，管理映射关系，分发事件到Handler | `frameworks/native/key_mapping/src/key_to_touch_manager.cpp` |
| **KeyMappingService** | 框架层 | 按键映射服务，检查游戏是否支持输入转触控，从SA获取配置 | `frameworks/native/key_mapping/src/key_mapping_service.cpp` |
| **GameControllerServerClient** | 框架层 | SA的InnerAPI客户端，封装IPC调用 | `frameworks/native/sa_client/src/gamecontroller_server_client.cpp` |
| **GameControllerServerAbility** | 服务层 | SA服务入口，系统服务ID 8450，实现IDL接口 | `service/ipc/src/gamecontroller_server_ability.cpp` |
| **DeviceManager** | 服务层 | 设备管理器，设备类型识别，设备信息同步和持久化 | `service/device_manager/src/device_manager.cpp` |
| **KeyMappingConfigManager** | 服务层 | 管理游戏的按键映射配置（默认和自定义） | `service/key_mapping_manager/src/key_mapping_config_manager.cpp` |

## 3. 组件依赖关系

```
【接口层依赖框架层】
GameDevice API → GameDeviceProxy → GameDeviceClient
GamePad API    → GamePadProxy    → InputEventClient

【框架层内部依赖】
WindowInputIntercept
    ├─→ InputEventClient (事件回调分发)
    ├─→ KeyToTouchManager (输入转触控)
    └─→ DeviceIdentifyService (设备类型识别)

MultiModalInputMonitor
    ├─→ DeviceIdentifyService (设备识别)
    ├─→ KeyMappingService (按键映射服务)
    └─→ GameDeviceClient (设备事件回调)

KeyMappingService
    ├─→ GameControllerServerClient (从SA获取配置)
    ├─→ KeyToTouchManager (更新按键映射)
    └─→ WindowInfoManager (窗口信息)

KeyToTouchManager
    ├─→ KeyToTouchHandler及其子类 (处理具体映射)
    └─→ GameControllerServerClient (与SA通信)

【框架层依赖服务层】
GameControllerServerClient → GameControllerServerAbility (IPC)
    ├─→ DeviceManager (设备管理)
    ├─→ GameSupportKeyMappingManager (游戏列表)
    ├─→ KeyMappingConfigManager (按键映射配置)
    └─→ EventPublisher (事件发布)

【外部系统依赖】
框架层
    ├─→ WindowManager (窗口系统：输入拦截、窗口信息)
    ├─→ MultiModalInput (多模输入：设备监听、输入事件)
    └─→ samgr (服务管理：拉起SA)
```

## 4. 系统分层结构

### 4.1 接口层
**编译产物**: `libohgame_controller.z.so`

**职责**：
- 对游戏开发者提供稳定的CAPI接口
- 定义数据结构和错误码
- 封装底层实现细节

---

### 4.2 框架层
**编译产物**: 
- `libgamecontroller_client.z.so` - InnerAPI客户端库
- `libgamecontroller_fwk_client.z.so` - 框架核心功能库
- `libgamecontroller_event.z.so` - 事件加载库

**职责**：
- 实现核心业务逻辑
- 对接外部系统（窗口、多模输入、samgr）
- 提供InnerAPI给终端厂商

**核心模块**：

1. **Window模块** - 对接窗口系统
2. **MultiModalInput模块** - 对接多模输入系统
3. **KeyMapping模块** - 输入转触控核心（17种映射处理器）
4. **Plugin模块** - 插件模式
5. **SA Client模块** - SA客户端

---

### 4.3 服务层
**编译产物**: `libgamecontroller_service.z.so`

**职责**：
- 提供系统服务（SA 8450）
- 设备管理和识别
- 按键映射配置管理
- 事件发布

**核心模块**：

1. **DeviceManager** - 设备管理
2. **KeyMappingManager** - 按键映射管理
3. **EventPublisher** - 事件发布
4. **GameControllerServerAbility** - SA服务入口

## 5. 关键数据流路径

### 5.1 设备上线事件流

```
1. 多模输入系统检测到设备上线
   ↓
2. MultiModalInputMonitor收到设备变化通知
   ↓
3. DeviceIdentifyService识别设备类型
   ↓
4. GameControllerServerClient.IdentifyDevice()
   → IPC调用 → GameControllerServerAbility
   ↓
5. DeviceManager执行设备识别逻辑
   ↓
6. 如果游戏支持输入转触控：
   KeyMappingService.BroadCastDeviceInfo()
   → KeyToTouchManager.UpdateTemplateConfig()
   ↓
7. 如果开发者注册了设备监听：
   GameDeviceClient回调通知应用
```

### 5.2 输入事件处理流

```
1. 窗口系统收到输入事件
   ↓
2. WindowInputIntercept.OnInputEvent()拦截事件
   ↓
3. 判断事件类型：
   
   [按键事件]
   ├─→ 如果开发者注册了监听：
   │   InputEventClient回调通知应用
   └─→ 如果游戏支持输入转触控：
       KeyToTouchManager.DispatchKeyEvent()
       → KeyToTouchHandler处理
       → 转换为触控事件注入系统

   [指针事件]
   └─→ KeyToTouchManager.DispatchPointerEvent()
       → KeyToTouchHandler处理
       → 转换为触控事件注入系统
```

### 5.3 输入转触控配置获取流

```
1. 应用启动时，窗口Framework加载libgamecontroller_event.z.so
   ↓
2. InputToTouchClient.StartInputToTouch()
   ├─→ 检查游戏是否支持输入转触控
   │   KeyMappingService.IsSupportGameKeyMapping()
   ↓
3. 如果支持，从SA获取配置：
   GameControllerServerClient.GetGameKeyMappingConfig()
   → IPC调用 → GameControllerServerAbility
   → KeyMappingConfigManager查询配置
   → 返回KeyToTouchMappingInfo列表
   ↓
4. KeyToTouchManager.UpdateTemplateConfig()
   ├─→ 创建InputToTouchContext
   ├─→ 初始化KeyToTouchHandler
   └─→ 注册需要监听的按键和鼠标
```
